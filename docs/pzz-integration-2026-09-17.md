## Исправления, найденные живой проверкой

1. Планировщик получает сведения о наличии слоёв и режиме из `pzz_inputs`.
   Содержимое файлов и идентификаторы загрузок в его контекст не попадают.
2. Наличие выбранного сценария больше не перекрывает файловый режим,
   извлечённый из запроса пользователя.
3. Колонки `Вид_использования_по_документу` и `Наименование_зоны` распознаются
   по точным алиасам. До исправления LLM выбрала кадастровый номер вместо ВРИ.
4. Контекст генерации ответа использует отдельные категории `by_verdict`.
   Пересекающиеся старые счётчики и неоднозначное пояснение upstream исключены
   из контекста ответа; исходный отчёт в SSE сохранён. Указан реальный формат слоя,
   запрещено реконструировать ID объектов и ссылки из итоговых количеств.
   Дополнительная проверка возобновления существующей задачи с настоящей LLM
   вернула правильные категории 194/13/1 и формат GeoJSON FeatureCollection.

После изменений маршрутизации и колонок: **1172 unit-теста пройдены**.
После финальной нормализации контекста: **52 профильных теста пройдены**, включая
новый тест сохранности исходного отчёта и отсутствия пересекающихся счётчиков
в контексте LLM. Black и isort пройдены.

## Границы проверки

Файловые расчёты выполнены по предоставленным слоям Долинска и Холмска;
сценарий 843 служил контекстом запросов и истории. Его геометрии не заменялись.
Режим расчёта по данным Urban API (`mode=scenario`) и режим зданий здесь не
проверялись. Резервный JSON проверен на загрузку и чтение; повторный расчёт с ним
не запускался, поскольку Excel успешно обработан. Успешный A2A-путь проверен
на выдаче уже рассчитанного результата, без повторной отправки классификации.
Браузерный интерфейс не проверялся. Полученные вердикты проверены на согласованность
слоя, отчёта и ответа; независимая нормативная экспертиза классификации не выполнялась.
