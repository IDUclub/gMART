## Подтверждённые причины

В запросе 10:04 МСК план содержал `pattern=3.3` без фильтра документа. В уточнении 10:07 МСК план переключился на семантический поиск и потерял номер пункта, документ и редакцию. Запросы: `7d2ab807-b208-4cb3-8849-5c3c5fea60a1` и `23092d1a-0b3e-495c-bce5-fa620e88527a`.

Поиск одного Градкодекса одной редакции возвращал девять кандидатов: реальные разные пункты, редакционные примечания с ошибочным номером и узлы с повреждённым путём. Это не девять документов. Полное название и редакция повторялись у каждого фрагмента, что дополнительно создавало впечатление дублей.

В 10:07:12 МСК сервер зарегистрировал отмену SSE; DVD в это время успешно выполнял запросы. Кто инициировал исходный обрыв, не установлен. Анонимный повтор через тот же gateway завершился за 15 секунд, поэтому постоянный таймаут в пять секунд не подтверждён.

## Что изменено

1. **Диалог gMART.** Незавершённый структурный вопрос сохраняется в Redis на 15 минут. Уточнение документа, даты редакции или статьи сужает прежний запрос; выбранные фрагменты привязаны к ID. Новый вопрос снимает прежнее ограничение. Одинаковые названия объединены в заголовок, ниже — короткие пути статей с выдержками и нумерованным выбором. Дедупликация по одному названию документа не применяется.
2. **Поток gMART.** Вычисление выполняется отдельной задачей; HTTP-соединения читают её журнал. `request_id` и `after_event` восстанавливают только недополученные события с `event_id`, не запускают повторный поиск. Проверка владельца и курсора выполняется до начала SSE. Явная отмена останавливает задачу. Потеря процесса обнаруживается по heartbeat и становится видимой ошибкой; автоматического продолжения вычислений после перезапуска процесса нет.
3. **Frontend.** Восстановление использует тот же request_id, ограничено тремя попытками подключения, отбрасывает повторные события и требует терминального события. Ошибка показывается в чате. Кнопка остановки отправляет явную отмену. Устаревший поток не меняет состояние нового запроса.
4. **Разметка DVD.** Оборванные редакционные фразы «введён/введена Федеральным законом от…» распознаются как примечания без самостоятельного номера. Исправление типа «Статья 52» и восстановление иерархии уже присутствовали в базе ветки; тестом закреплён наблюдавшийся заголовок с табуляцией. Для существующих данных нужен переразбор исходника.
5. **Каталог DVD.** Общий каталог читает тот же общий индекс Qdrant, что поиск, включая документы без записи в Redis. Причина исходной потери/неполноты регистрационных записей не установлена. Отдельный список готовых пользовательских документов сохраняет проверку завершённой регистрации.
6. **Адресный переразбор DVD.** `/documents/reparse` поддерживает точные `name`, `version` и `dry_run`; предварительный просмотр возвращает `planned` и не создаёт задания. Неизвестное имя не переключает операцию на весь корпус.

## Проверки

- gMART: **895 unit-тестов прошли в Linux на базе dev**, включая разрыв подписчика при работающем поиске, два одновременных подключения, однократное выполнение, курсор, чужого владельца, явную отмену, выбор статьи и сохранение пункта после уточнения редакции. Ранее на SDK-базе проходили 949 тестов; разница связана с исключёнными из PR SDK-коммитами.
- IDU_DVD: **857 unit-тестов прошли**, включая каталог без registry, разметку, предварительный просмотр и выбор одной редакции для переразбора.
- Frontend: `npm run typecheck`, `npm run build`, `node --test tests/documentStream.test.mjs` — успешны; три сценария проверки SSE, включая разбиение UTF-8/CRLF на сетевые порции и повторные события.
- Изменённые Python-файлы проходят Black (Python 3.11) и isort; `git diff --check` не выявляет ошибок пробелов. Графы кода обновлены AST-командой `graphify update .` во всех трёх worktree.

Тесты используют подмены внешних сервисов. Это проверка программных дефектов и контракта восстановления; полного повторения исходного диалога на обновлённом dev пока нет. Linux-проверка: `python -m pytest tests/unit -q --tb=short --show-capture=no -p no:cacheprovider` в одноразовом контейнере без сети, с зависимостями приложения и pytest/pytest-asyncio/fakeredis.

## Что осталось на dev

1. Проверить исходный DOCX Градкодекса локально с новой разметкой: число настоящих пунктов, полные пути статей, отделение редакционных примечаний, сохранение текста и дочерних фрагментов. Пользователь явно разрешил скачивание 14.09.2026; ограничение разрешений снято. Однако dev возвращает HTTP 404 «исходный файл недоступен» как с точной редакцией, так и без параметра version. Свежий `/documents?name=…` подтверждает единственную ожидаемую редакцию и прежний doc_id. Файл не скачан. Код endpoint объединяет отсутствие source_object_key и ошибку чтения MinIO в один ответ 404; по этому ответу нельзя установить, потерян ли сам объект или ссылка на него. Нужна проверка метаданных индекса и хранилища исходников либо исходный файл из резервной копии. Скрипт скачивания находится в игнорируемом `docs_data/dev-diagnosis-20260914/` worktree DVD.
2. После проверки и публикации DVD убедиться по OpenAPI, что `/documents/reparse` действительно поддерживает все три новых параметра. **Старый API может проигнорировать неизвестные параметры, включая `dry_run`, и поставить весь корпус на переразбор.** Не отправлять такой preview в старую версию.
3. Выполнить preview только для точного имени и редакции, проверить единственную цель с doc_id `c68ed292-457f-4b0e-bd4f-6c13edc4df88`, затем адресный переразбор. Дождаться успешного задания и сравнить индекс с оригиналом. Не удалять документы и не запускать переразбор всего корпуса.
4. Обновить gMART, затем frontend. Проверить оба хода исходного диалога и выбор конкретной статьи; имитировать отключение сети в браузере и убедиться, что запрос выполняется один раз, ответ восстанавливается без повторов, а явная остановка прекращает работу.
5. Для точного источника исходной отмены сопоставить gateway access logs и browser network/console trace. Kubernetes-контекст в текущем окружении не настроен; gateway logs в этой проверке не получены.

Диагностические логи исходного расследования находятся в исходном gMART в `output/dev-diagnosis-20260914/`; в коммит с исправлениями они не включаются. Токены и исходные документы в отчёт не включены.
