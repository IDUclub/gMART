# Стабилизация индустриальной приёмки

Продолжение диагностики `2026-09-14-industrial-harness.md`. Критерий остаётся
15/15 независимых двухрепликовых диалогов на одной сборке: по три формулировки
каждого из пяти сценариев. Отрицательная оценка проекта допустима; незавершённый
анализ и `needs_review` оценщика не считаются успехом. Новые агенты не подключались.

## Воспроизведённые причины

1. **Потеря области задачи при делегировании.** Контроллер сокращал исходные
   условия, а формирование цели не всегда сохраняло ограничения предыдущей
   пользовательской реплики. Теперь описание обязательного результата неизменно,
   исходные цитаты доступны специалистам, предыдущие условия можно цитировать.
   История ответов специалистов не дублируется целиком при формировании цели.
2. **Неоднозначная цель.** Модель выдавала английские описания для русских
   инструментов, объединяла физические типы в нетипизированную выборку и путала
   расчёт услуги с получением исходных услуг. Валидация требует язык запроса,
   восстанавливает однозначный вид сущности из цитаты, разделяет явно названные
   типы, сохраняет фильтры и оставляет итоговое сравнение оркестратору.
   Схема поддерживает до 32 требований; цель получает до двух попыток исправления.
3. **Функциональные зоны.** Выбирался инструмент проекта без геометрии зон;
   требуемые источник и год не разрешались через каталог. Теперь рабочий клиент
   сначала получает каталог источников зон. Единственный вариант используется
   с его реальным годом; неоднозначность требует уточнения.
4. **Контекст и сравнение.** Подробные таблицы и источники вытеснялись каталогами;
   отдельные таблицы не имели видимого ID сценария. Подтверждённые результаты
   приоритетны в представлении контекста. Арифметика сравнения обеспеченности
   выполняется по ссылкам на реальные ячейки с проверкой области и единиц.
   Поддерживаются и сводная таблица, и отдельная таблица метрик услуги; частичный
   набор сравнений модели дополняется запрошенными сравнениями подтверждённых
   ячеек. Это проверено на смешанном представлении двух сценариев.
5. **DVD и стенд.** Сначала VPN не позволял разрешить `a.dgx`. После восстановления
   связи поиск в области синтетического сценария продолжал падать: DVD обращался
   к настоящему Urban API. Overlay теперь направляет его проверку принадлежности
   сценария к тому же контрольному источнику. Preflight включает реальный поиск
   через DVD, удалённые эмбеддинги и эту проверку области.
6. **Каноническая проверка расстояния.** Любое число с единицей длины переводило
   compliance в свободный планировщик, даже если это цитата канонического пункта.
   Теперь совпадающая цитата документа/версии/пункта использует сохранённый CheckPlan.
   Временное изменение расстояния сохраняет отдельный путь. Полный обход NormGraph
   ограничивается указанными документом, версией и пунктом; другая редакция не
   подменяет запрошенную. Детерминированный регрессионный тест воспроизводил вызов
   неправильного обработчика, затем прошёл на исправлении.
7. **Оценщик и воспроизводимость.** Судья получает короткие ссылки на реальные
   цитаты ответа и артефакты, сохраняя карты соответствий. Производный текст
   специалистов не используется как независимое доказательство. Одна попытка
   исправления допустима только для некорректного формата/ссылок; уже полученные
   отрицательные оценки код сохраняет. В fingerprint учитываются именно контейнеры
   compose, а не временный контейнер unit-тестов с унаследованными метками образа.

Эти изменения не задают порядок вызовов агентов и не подставляют контрольные
результаты в ответы. Контрольные значения используются только при проверке.

## Проверка кандидата

- Windows: 1132 unit-теста прошли; файл с `fcntl` проверен в Linux.
- Linux: все 1137 unit-тестов прошли, включая дополнительную регрессию сравнения.
- `black` и `isort` прошли.
- Реальный preflight: транспорт источников, scoped DVD, девять расчётных сценариев,
  50-метровая геометрия и новый маршрут canonical compliance прошли.
- Новый probe вызывает настоящий обработчик compliance, реальные NormGraph,
  Redis и IDU MCP без вызова LLM: исходный вариант 91001 имеет одно нарушение,
  исправленный 91006 — ноль, в обоих проверен один объект.
  Проверены также исходная геометрия, идентификаторы, версия и оба слоя результата.
- Graphify обновлён: 6025 узлов, 15117 связей. Это AST-обновление без вызовов модели.

Логи и полные ответы лежат в `output/industrial/` исходной рабочей копии:
`stability-candidate-unit-04.log`, `stability-linux-unit-04.log`,
`stability-canonical-preflight-03/`, `stability-graphify-update-final.log`.

## Живая приёмка

Модель остаётся `gpt-oss-20b` на `http://10.32.11.27:8001/v1`.
Сервер сообщает окно 65536 токенов. Формирование цели — medium, готовый
аналитический синтез — high. Overlay допускает 800000 суммарных токенов,
120 вызовов модели, 160 инструментальных вызовов и 600 секунд на анализ.
Это верхние границы, не обязательный расход.

Пользователь разрешил до трёх полных серий. Исходные результаты сохраняются,
перезапись каталогов запрещена. `stability-01` остановлена после выявления
повторяющихся причин; `stability-02` завершилась на проверке fingerprint до
аналитических запросов, поскольку временный unit-контейнер попадал в инвентарь.
Вторая аналитическая попытка — `stability-02-live` на `9a09074`.

Окончательный результат третьей серии будет внесён после её выполнения.
Успешный preflight и unit-тесты сами по себе не подтверждают 15/15.
