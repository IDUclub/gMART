# Логирование Redis на стороне agents

Общий `LoggedRedis` используется хранилищами PipelineStateStore и SynapseRunStore.
По умолчанию успешные команды записываются на уровне INFO, ошибки — ERROR,
отмена операции — WARNING. Записи попадают в обычные логи agents (консоль и файл).

Пример формата (значения условные):

```text
Redis command=GET endpoint=gmart-redis:6379/0 pid=42 request_id=12345678-1234-1234-1234-123456789abc key_kind=pipeline:state attempt=1 outcome=error duration_ms=5.21 error_type=ConnectionError
```

Поля показывают команду, адрес Redis без реквизитов доступа, базу, PID процесса,
идентификатор запроса, вид ключа, попытку, результат и длительность в миллисекундах.
`attempt` отражает повторы PipelineStateStore. Идентификатор запроса берётся из
контекста операции или известного формата ключа; если UUID недоступен, записывается `-`.
Произвольные ключи и неизвестные команды обозначаются `other` / `OTHER`.
Значения, ответы Redis, аргументы команд, Lua-скрипты, токены, пароли и текст
исключений в эти диагностические записи не включаются.

Транзакция записывается при исполнении одной строкой `EXEC` со списком команд
и их количеством. Постановка команды в очередь не считается исполнением.
WATCH и чтения до MULTI записываются отдельно. Для пакета без транзакции используется
`PIPELINE`. Возвращённые ошибки при `raise_on_error=False` отмечаются `partial_error`.

Для команд Pub/Sub `outcome=sent` подтверждает отправку, но не обработку подписчиком.
Сбои чтения Pub/Sub отмечаются `PUBSUB_READ`; содержимое сообщений и пустые циклы
ожидания не записываются. Это журнал вызовов клиента приложения: внутренние AUTH,
handshake и health-check PING библиотеки не являются отдельными записями.

Настройка `REDIS_LOG_COMMANDS=true` включает все успешные операции и ошибки.
`REDIS_LOG_COMMANDS=false` оставляет ошибки и отмены; отдельные предупреждения о
повторах тоже сохраняются. Переменная добавлена в пример env и deploy compose.
Для появления логов на develop нужно обновить образ и пересоздать контейнер agents.
