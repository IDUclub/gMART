# Проверка динамического бюджета DVD RAG — 10 сентября 2026

Изменение исправляет остановку финальной генерации по `length` и добавляет продолжение
видимого текста с проверкой стыка. Оно не меняет поисковую модель или правила семантического
критика и не гарантирует устранения всех ранее выявленных смысловых ошибок.

## Проверки

- Полный unit-набор в одноразовом Linux-контейнере: **826 passed**.
- Регрессии охватывают рост бюджета, предел окна, историю, сокращение источников при
  повторе, пустой результат после рассуждений, исчерпание повторов, ошибку фильтрации,
  EOF без подтверждения завершения, перекрытие фрагментов и replay неуспешного запроса.
- Проверка с настоящим `gpt-oss-20b`: копирование 80 синтетических фактов.
  Первый вызов: бюджет 1152, `finish_reason=length`, 4039 байт видимого текста.
  Второй: бюджет 2304, `finish_reason=stop`; предыдущий текст передан как assistant-сообщение.
  Все 80 фактов сохранены ровно по одному разу. Тест занял 8.96 с.
- Проблемный запрос «Какие требования влияют на размещение школ?» выполнен локальным
  исправленным пайплайном с реальными dev DVD MCP и удалённой моделью:
  `temperature=0` — 18.4 с, принят второй черновик;
  `temperature=1` — 9.5 с, принят первый черновик.
  Бюджет генерации — 8704 при окне 65536. Ошибок генерации нет; ответ корректно
  сообщает о недостаточности найденных фрагментов, не выдумывая требования.

В этих двух проверках пайплайна Redis заменён fakeredis, сохранение в ChatStorage отключено.
Это проверка изменённого локального кода с живыми зависимостями, а не результат деплоя.

## Воспроизведение

```bash
uv run pytest tests/unit
VLLM_BASE_URL=http://<server>/v1 VLLM_MODEL=gpt-oss-20b \
  uv run pytest tests/integration/test_dvd_answer_budget_live.py -q -s
uv run pre-commit run --all-files
```

Unit-набор требует Linux (`fcntl`) и тестовую auth-конфигурацию из `.github/workflows/tests.yml`.
Live-тест выполняется только при заданном доступном endpoint; тестовые факты не являются
строительными нормами. Детальные логи локальных прогонов сохранены в `tmp/diagnostics/`
рабочего окружения и не включены в Git.
