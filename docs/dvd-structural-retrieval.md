# Документальный агент: адреса, наименования и большой контекст

Планировщик выбирает `retrieval_mode`: semantic, structure или name.
Явный адрес пункта имеет приоритет над переформулировкой модели. Например,
`о чем говорится в пункте 3.3 СП 2.13130.2020 2020?` превращается в
`search_structure(request={pattern:"3.3", document_names:["СП 2.13130.2020"],
include_children:true})`. Фильтр `types=clause` не добавляется: пункт может
оказаться определением, таблицей или другим элементом.

`document_names` обозначает документ, `name_query` — собственное наименование
фрагмента. `name_scope=self` ищет только собственное имя, `path` — также имена
предков. `name_mode=strict` использует нормализацию/подстроку/маску, `expanded`
добавляет близкие словоформы, опечатки и семантику наименований. Совместно с
`pattern` это AND, а не запасной поиск после отсутствия адреса.

Примеры намерений и параметров:

| Вопрос | План |
|---|---|
| Пункт 3.3 документа | structure; pattern=3.3; include_children=true |
| Пункты 3.3–3.5 | structure; pattern=3.3–3.5; allow_multiple=true |
| Пункты приложения А | structure; pattern=А; include_children=true |
| Найди определения огнезащитного покрытия | name; name_query=огнезащитное покрытие; name_mode=expanded |
| Пункт 3.3 внутри раздела «Защита» | structure; pattern=3.3; name_query=Защита; name_scope=path |

Сервис читает все страницы по `next_cursor`. Критик и повторная попытка не могут
изменить зафиксированные документ, редакцию, путь и наименование. При нескольких
кандидатах агент спрашивает уточнение, если пользователь не запросил обзор,
сравнение или множество элементов. При отсутствии адреса ответ явно сообщает
об этом; семантический поиск с ослабленными ограничениями не подменяет результат.

## Большой контекст

Контекст больше не обрезается до 1500 символов на источник. Если все фрагменты
не помещаются в запрос вместе с вопросом, историей и резервом ответа:

1. Текст делится без потери символов. Части сохраняют обозначения источников.
2. Ограниченное число запросов выполняется параллельно. Каждая часть даёт
   выжимку сведений, относящихся к вопросу, включая условия, исключения, числа,
   единицы, отрицания и расхождения между источниками.
3. Отдельный запрос проверяет выжимку по исходной части и восстанавливает пропуски.
4. Проверяются метки источников и признак полноты. При необходимости выжимки
   объединяются через следующие уровни обработки; затем формируется общий ответ.

Входной текст документов считается данными, а не инструкциями. Проверка меток
и второй проход уменьшают риск пропусков, но не являются математической гарантией
смысловой полноты LLM. Для приёмки нужен также прогон реальных вопросов на выбранной
модели с проверкой условий, исключений и цитат специалистом.

Ошибки части повторяются до двух раз. После исчерпания повторов выдаётся событие
`warning` с кодом `document_context_incomplete` и перечнем частей/источников;
ответ начинается с явного указания неполноты. При несходящемся сжатии, превышении
числа страниц/уровней, переполнении итогового запроса или обрыве генерации по лимиту
пайплайн возвращает ошибку, а не успешный полный ответ. Отмена распространяется
на параллельные запросы.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| DVD_CONTEXT_WINDOW_TOKENS | 8192 | Окно установленной модели, минимум 4096 |
| DVD_ANSWER_MAX_TOKENS | 1536 | Резерв/лимит ответа; увеличивать вместе с окном для длинных ответов |
| DVD_CONTEXT_CONCURRENCY | 4 | Одновременные запросы внутри одного документального пайплайна, 1–16 |
| DVD_RETRIEVAL_MAX_PAGES | 100 | Максимум страниц по 100 фрагментов; превышение — явная ошибка |

Расход входа оценивается консервативно по байтам UTF-8 без зависимости от
конкретного токенизатора. Для Ollama передаётся `num_ctx`; на OpenAI-совместимом
сервере реальное окно модели должно быть настроено на сервере. Суммарная нагрузка
при нескольких пользовательских запросах умножается на число пайплайнов.
Событие `context_processing` показывает обработку частей. Метрики количества
успешных/неуспешных частей и уровней сохраняются в checkpoint.

Развертывание требует IDU_DVD с инструментами `search_structure` и
`search_fragment_names`. Сначала обновляется DVD, затем агент. Полный unit-набор
gMART включает Linux-модуль `fcntl`; на Windows запускается документальный набор,
полный прогон выполняется в Linux/CI.
