# Корректность ответов Scenario Data

Изменения от 9 сентября 2026 года закрывают ошибки, воспроизведённые на сценариях
772 и 848 с локальной `gpt-oss-20b`. Исходный отчёт и реальные трассы находятся в
`benchmarks/out/scenario_data_20260909.md` и `benchmarks/data/scenario_data_20260909/`.

## Контракт простого запроса

Для количества, списка и карты сущностей одного типа агент получает актуальные
справочники физических объектов **и** сервисов выбранного сценария. Модель сначала
определяет операцию независимо от наличия типа в каталоге, затем отдельным вызовом
выбирает кандидата из справочника, если нет единственного точного совпадения названия.
Точное совпадение определяется кодом. Отсутствие кандидата не меняет операцию и не разрешает
расширение выборки. Числовой ID типа определяется по записи
справочника на стороне приложения. Типы и номера сценариев не зашиты в код.

После выбора приложение вызывает инструмент выбранного сценария с явным фильтром
типа. Оно проверяет тип и идентификатор каждой записи, исключает дубликаты и отклоняет
ответы с признаками неполной выборки. Количество и таблица строятся из этой выборки.
Для карты дополнительно проверяется равенство наборов идентификаторов в обычном
ответе и GeoJSON. Посторонние объекты не могут попасть в слой под названием выбранного
типа. При превышении лимита встроенной таблицы ответ явно сообщает о её усечении.

Справочники сценария содержат представленные в нём типы. При отсутствии кандидата
агент дополнительно проверяет общие справочники, если инструменты доступны. Известный
тип с успешно полученной пустой выборкой даёт **0**. Неизвестный или неразрешённый тип
вызывает уточнение. Неуверенность при повторном сопоставлении не разрешает переход к
нефильтрованной выборке.

## Защита обычного планирования

- Запрос конкретного типа больше не попадает в обработчик распределения всех типов.
- В коротком списке инструментов сохраняются обе сущности и их справочники сценария.
- Названия типов сохраняются в агрегатах даже при большом количестве полей адреса
  и здания. В контекст ответа передаются назначение и область источника.
- Отсутствие полученных данных и один только справочник не подтверждают количество
  объектов. Некорректный ответ проверяющей модели не считается успешной проверкой.
- В обычном цикле планирования таблицы и слои отправляются после проверки ответа.
  После исчерпания повторных попыток отклонённый фактический текст и его артефакты
  не публикуются. Название промежуточного слоя берётся из инструмента-источника.

Запросы с дополнительными условиями, например по этажности, радиусу или окружению,
остаются в общем планировщике. Этот набор испытаний не устанавливает их общую точность.
Экспериментальный линейный/workspace процесс целиком не оценивался реальными прогонами.

## Проверка

Офлайн: `tests/unit/test_scenario_data_selection.py` проверяет фильтры, настоящую пустую
выборку, неизвестный тип, повторное сопоставление, дубликаты, несовпадение карты и таблицы,
неполные данные и запрет публикации отклонённого результата. Регрессии агрегации и
проверки ответа покрыты отдельными тестами.

```powershell
$scenarioTests = @(Get-ChildItem tests/unit/test_scenario_data*.py | ForEach-Object FullName)
.venv/Scripts/python.exe -m pytest @scenarioTests tests/unit/test_urban_mcp_client.py tests/unit/test_llm_adapters.py -o 'pythonpath=. src' -q
```

Реальные испытания запускают сам сервис с настоящими LLM, Urban MCP и REST Urban API.
Состояние заменено на fakeredis, история чата отключена. Эталон получен отдельно через
REST; проверяются точные количества и наборы идентификаторов, согласованность текста,
таблицы и карты, а также аргументы запросов. Пользовательский интерфейс и развёрнутый
контейнер этим запуском не проверяются и не обновляются.

Команды и итоговые результаты: `benchmarks/out/scenario_data_fixes_20260909.md`.
Каталог `benchmarks/` локальный и исключён из Git; регрессионные unit-тесты и эта
документация находятся в исходниках проекта.

## Показатели и сравнение сценариев

Запросы показателей обрабатываются отдельным `ScenarioAnalytics`, до общего
планировщика и обработчика типов объектов. Для каждого сценария агент с токеном
пользователя читает `GetScenarioById`, затем `GetScenarioIndicatorsValues`.
Сравнение поддерживает явно указанные ID сценариев; ID из текста не заменяется
выбранным сценарием. Обычное планирование по-прежнему ограничено выбранным сценарием.
Каждый вызов записывает фактический scenario_id в аргументах и MCP meta.

Модель получает компактный каталог названий и единиц и выбирает показатели.
Значения, единицы, ID и арифметика не генерируются моделью. Приложение проверяет
принадлежность ответа сценарию, конечность чисел, дубликаты, противоречия и признаки
неполной выборки. Для ответов уровня сценария исключаются значения территорий и
гексагонов. Отсутствующее значение не заменяется нулём или похожим показателем.
В частности, «Население» без единицы нельзя использовать как численность людей.

Поддерживаются значения одного/нескольких показателей, полный перечень, пояснения
из комментариев источника, сравнение по ID показателя с проверкой единиц,
разница, процент изменения и расчёт плотности населения. Процент изменения —
разница, делённая на модуль исходного значения; при нуле процент не определён.
Для долей в процентах разница выводится в процентных пунктах. В явном запросе
«относительно 772» исходным становится 772 независимо от порядка перечисления.
Сохранённая плотность и вычисленная по численности/площади показываются отдельно;
причина расхождения не выдумывается. Комментарии атрибутируются источнику.

Сравнение общего количества сервисов/физических объектов использует полные
коллекции соответствующих сущностей с удалением дубликатов по ID. Сценарии из
разных проектов допускаются, это отмечается в ответе. При ошибке получения второго
сценария частичная выборка не публикуется как сравнение.

Ограничения: до 8 явно указанных сценариев в одном сравнении; поиск по названиям
сценариев не реализован. Специальная аналитика не выполняет произвольные формулы,
пространственную фильтрацию показателей и сравнение сущностей с дополнительными
фильтрами. Запросы карт и фильтров требуют отдельного сценария обработки.

Регрессии: `tests/unit/test_scenario_data_indicators.py`. Итоговый живой набор:
`benchmarks/harness/eval_scenario_complete_regression.py` (до 64 запросов одновременно).
Независимый эталон проверяет точные пары название/значение/единица, таблицы,
отсутствующие значения, вычисления и получение данных каждого сценария.
Наличие таблицы или слоя больше не отменяет отрицательный вердикт проверки
содержания ответа в общем планировщике.
