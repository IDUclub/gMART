# Проверка документального агента 10 сентября 2026

Исходный вопрос: «Какие требования влияют на размещение школ?».
На dev с gMART `96223f1` запрос завершился ошибкой через 225,12 с:
21 из 22 частей контекста не прошли обработку. Повторное подключение корректно
воспроизводило ошибку, но сам вопрос оставался без результата.

## Причины и исправления

1. Резервное окно 8192 использовалось при фактическом `max_model_len=65536`
   у gpt-oss-20b. Контекст размером 34 324 байта без необходимости разбивался
   на множество частей. Окно теперь читается из метаданных выбранной модели;
   явная настройка остаётся верхней границей. Бюджет изолирован между запросами.
2. Библиографические ссылки `[10]` внутри документа считались отдельными
   источниками. Границы источников теперь задаёт приложение, независимо от
   квадратных скобок в исходном тексте.
3. Свободная выжимка могла терять метки и менять смысл, например переносить
   норму о гостинице на школу. Сжатие теперь извлекает проверяемые дословные
   цитаты отдельно по источникам. При изменении моделью исходного написания
   повтор выбирает индексы фрагментов, а текст копирует приложение.
   Второй проход проверяет выбор. Нерелевантные части учитываются в проверке
   покрытия, но их длинные заголовки не повторяются в итоговом контексте.
4. Критик принимал аналогии между видами зданий и отвергал честный недостаток
   данных. Инструкции и схема теперь требуют сначала перечислить ошибки и
   пропуски. Наличие ошибок отменяет положительный вердикт. Явные расшифровки
   сокращений и номера таблиц дополнительно сверяются с исходным текстом.
   Все замечания сохраняются между попытками, чтобы очередная версия не
   возвращала уже исправленную ошибку.
5. gMART не передавал `context_height` в структурный поиск. DVD, в свою очередь,
   принимал этот параметр, но возвращал `context=null`. Исправление DVD:
   [IDU_DVD #76](https://github.com/IDUclub/IDU_DVD/pull/76).
   Продолжение предложения в соседнем фрагменте восстанавливается без изменения
   совпадений и пагинации, с сохранением области доступа.

## Проверки

- Полные unit-наборы: **807 тестов gMART прошли в Linux**, **809 тестов DVD прошли**
  в его штатном Python-окружении. Форматирование black/isort проверено.
  Новые регрессии проверяют библиографию, цитаты, подмену области применения,
  метаданные окна, параллельные запросы, выбор фрагментов и ошибки критика.
- `tests/integration/test_dvd_evidence_live.py`: 10 контрольных случаев с
  `VLLM_BASE_URL` и `VLLM_MODEL=gpt-oss-20b`, включая недостаток данных,
  ложную аналогию, ошибочное число, оглавление, расшифровку и номер таблицы.
  Часть проверок намеренно выполняется кодом до обращения к критику.
- Реальный DVD MCP + удалённая модель, новый код gMART: исходный запрос
  с автоматическим окном завершился за 9,5 с. Ответ указывает на отсутствие
  применимых требований **в найденных фрагментах**, не утверждает их отсутствие
  во всей нормативной базе и не переносит нормы других типов объектов на школы.
- Вопрос о вместимости гостиницы для приезжих при проектировании ЛИУ/ЛПУ:
  контекст около 80 КБ. Проверка отклонила два неверных черновика; принятый ответ
  верно указал задание на проектирование, сохранил область ЛИУ/ЛПУ и ссылки [1], [7].
  Финальный прогон занял 78,5 с. Предыдущие прогоны также выявляли повторное
  появление уже исправленных ошибок; для этого добавлено накопление замечаний.
- Исправленный DVD проверен на пункте 31.6.1 и его соседях, прочитанных через
  `/library/nodes` со стенда. Восстановлены ссылка на 27.3 и продолжение о задании
  на проектирование. Новый gMART с удалённой моделью ответил на этот сохранённый
  результат за 5,8 с.

Для локального воспроизведения пайплайна состояние Redis было заменено fakeredis,
история чата не сохранялась. Эти проверки подтверждают новый код с реальными
зависимостями/сохранёнными фрагментами, **не выкладку нового кода на dev**.

## Ограничения и выкладка

Принудительное окно 8192 не вместило проверку длинного черновика: прогон завершился
ошибкой `Incomplete structured answer; no context capacity for a larger output budget`.
Это не успешный ответ. Для текущего gpt-oss-20b следует оставить автоматическое
определение окна либо согласовать явную границу с сервером (сейчас 65536).
Малые окна и большие ответы могут требовать ограничения запроса или увеличения окна.

Выбор цитат и смысловая проверка остаются вероятностными. Набор регрессий не
доказывает точность модели на любых нормативных вопросах. У найденных документов
есть проблемы разбиения/метаданных; восстановление соседей не переиндексирует
корпус и не исправляет все его исторические данные.

Порядок выкладки: DVD #76, затем согласованный PR gMART; после выкладки повторить
исходный вопрос и точный запрос пункта 31.6.1 через SSE самого dev-сервиса,
проверить итоговый ответ, терминальный статус и логи. Черновые SSE-события имеют
`done=false`; принимать/сохранять следует только подтверждённую итерацию.

CI DVD #76: unit-тесты и Kafka прошли. Ingestion/integration job упал на внешнем
`urban-api.testing.idulab.ru`: `/api/v1/territories_without_geometry` возвращал
HTTP 500 при поиске Выборга/Выборгского района. Этот запрос не проходит через
изменённый структурный поиск. Не следует объявлять весь CI успешным или скрывать
этот контрактный сбой отключением теста.
