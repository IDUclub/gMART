# Подтверждённые ошибки и изменения

1. **Compliance был недоступен оркестратору**, хотя имел отдельный рабочий процесс. Добавлен шестой предметный маршрут с передачей NormGraph; описание restriction ограничено геометрической ролью.
2. **Планировщик терял выбранный сценарий и изменения из истории.** Теперь scenario_id передаётся в доверенном контексте, история завершённых задач отделена от current_request. Добавлены правила обработки составных задач, недоступных агентов, новых чисел и ID сравнения. Более трёх шагов вызывает уточнение, а не обрезание плана.
3. **Невалидные планы поиска DVD** содержали null вместо обязательных enum-полей и строку «null» вместо отсутствующего фильтра. Добавлены JSON Schema и нормализация отсутствующих фильтров. Сервису поиска передаётся подтверждённый DI user_id вместе со сценарием; модель не выбирает эту личность.
4. **«Школы» ошибочно объявлялись отсутствующим сервисом**, хотя каталог содержал «Школа». JSON Schema обеспеченности ограничена настоящим каталогом; убран пример с неверной словоформой.
5. **Compliance игнорировал пользовательские 50 метров**, сразу переходя к пустому набору канонических правил. Явное расстояние теперь проходит через существующий план конкретного запроса с пользовательским происхождением условия. Числа из текстовой выжимки предыдущих шагов не должны включать этот режим сами по себе.
6. **Количество буферов выдавалось за количество затронутых объектов.** Итог построения буферов теперь формируется по возвращённым геометриям и явно сообщает, что пересечения не проверялись. Пустые коллекции не требуют вычисления UTM для текстового итога.
7. **Уточнения исполнителей считались успешными расчётами.** Добавлены события clarification, статус needs_clarification и соответствующая обработка интерфейсом/историей. Неуспешные черновики и таблицы не сохраняются как подтверждённый результат.
8. **Пустой граф приводил к советам с выдуманными обозначениями документов.** Для отсутствующей выдачи используется фиксированное сообщение о невозможности подтвердить норму; отсутствие записи не объявляется отсутствием требования.
9. **Последняя попытка и ошибка критика автоматически подтверждали черновик.** Убрано это поведение: без положительной проверки по источникам ответ не считается подтверждённым; лимит попыток остаётся ограниченным.
10. **Неверная интерпретация обеспеченности:** среднее 0,874 по зданиям выдавалось за покрытие общего спроса; медиана 1 — за состояние половины школ. Уточнения промпта оказалось недостаточно. Поэтому числовые ответы одиночной и сводной обеспеченности теперь формируются непосредственно из результатов Effects; среднее и медиана подписаны как показатели по зданиям. 3060/3637 даёт 84,1%, а не 87,4%. В mix-001 число 3 из списка школ больше не заменяет 4 объекта расчётного контура. Ошибка/отсутствие расчёта получает статус failed; пустой каталог вызывает уточнение без обращения к модели с невалидным enum.

## Что ещё ограничивает результат

- Локальный NormGraph возвращает пустой набор канонических правил. Содержательную полноту проверки норм на таком графе подтвердить нельзя.
- Локальный DVD не предоставляет search_structure/search_fragment_names. Для точного поиска пункта/названия нужен обновлённый сервис. Подменять точный поиск семантическим и сообщать об успехе нельзя.
- Пересоздание DVD/NormGraph не выполнялось: автоматическая проверка отклонила способ, который сохранял всё окружение контейнеров, из-за возможного копирования секретов. Этот скрипт удалён; учётные данные контейнеров не копировались.
- Предметные типы из синтетического набора не все представлены в сценарии 772. Корректное уточнение отличается от выполненного расчёта.
- Между шагами передаётся текстовая выжимка до 1500 символов, а не полные слои/таблицы. После ошибки или уточнения пропускаются и независимые следующие шаги. Эти архитектурные ограничения сохранены и учитываются при оценке полноты mixed.
- Свободный текст всё ещё может содержать неверные формулировки. Ни событие completed, ни оценка той же модели не доказывают универсальную достоверность.
- Проверка цитат обнаружила пересказ таблицы внутри кавычек (mix-054). Числа присутствуют в источнике, но дословная точность и интерпретация прочерков как отсутствия применимых норм не подтверждены. Для mix-003/mix-042 расхождения цитат относятся к пунктуации, а не выдуманным числовым расстояниям.
- Проверка самого LLM-судьи выявила ошибки: например, для orch-018 он путал три показанных примера свойств с feature_count=9, а для orch-026 предполагал существование записи нормы без доказательств. Поэтому его оценки исключены из метрик качества; сохранены только как необработанный диагностический эксперимент.
- Исходный полный прогон выполнялся без доступных локальных эмбеддингов. Перед повторным запуском сервис bge-m3 восстановлен; эффект этого изменения отделён от результатов маршрутизации.
