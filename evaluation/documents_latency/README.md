# Задержка агента документов (`/documents/qa/stream`)

Бенчмарк к плану ускорения RAG по нормативным документам. Он сравнивает две
развёрнутые версии gMART на одном замороженном наборе запросов. Отчёт имеет
формат раздела 11 плана и строится отдельно по каждому классу запросов.

## Состав

- `cases.json` — замороженный набор классов A–H: A — точные ссылки, B — смысловые
  вопросы, C — числовые требования, D — применимость и исключения, E — нет
  данных, F — длинный контекст, G — многоходовые диалоги, H — перечни
  документов. В нём 36 стартовых запросов. Для чекпоинтов плана набор нужно
  расширить до 100–200 запросов, из них не меньше 30 с длинным контекстом.
  После первого прогона набор не меняется.
- `run_http.py` — прогоняет набор через HTTP по одному запросу (параллельные
  запросы делят один сервер LLM и искажают задержку) и сохраняет JSONL.
- `report.py` — сравнивает два прогона и печатает таблицы в Markdown.

## Что измеряется

Каждое событие SSE получает временную метку на клиенте. По переходам статусов
(`retrieval_planning` → `searching` → … → `finalizing`) время раскладывается по
этапам для любой версии, в том числе для baseline без серверных метрик. Начиная
с этапа 0 сервис пишет строку `DVD run metrics {json}`: время этапов на сервере,
число вызовов LLM, токены, решения пайплайна (`planner_bypassed`,
`critic_reasoning_effort`, `first_draft_accepted` …). После прогона `run_http.py`
один раз скачивает `/system/logs` и прикрепляет эти записи по `request_id`.

Ответ не отдаётся по частям, пока критик его не принял. Поэтому TTFT (первый
непустой фрагмент ответа) почти равен полной задержке, и сокращать его можно
только вместе с ней.

## Запуск

```powershell
uv run python evaluation/documents_latency/run_http.py --base-url http://10.32.11.90:31004 `
    --label baseline-0.21.2 --out benchmarks/data/documents_latency/baseline.jsonl
uv run python evaluation/documents_latency/run_http.py --base-url http://10.32.11.90:31004 `
    --label fasten-rag --out benchmarks/data/documents_latency/fasten-rag.jsonl
uv run python evaluation/documents_latency/report.py `
    benchmarks/data/documents_latency/baseline.jsonl `
    benchmarks/data/documents_latency/fasten-rag.jsonl --labels labels.jsonl
```

Одноходовые запросы выполняются анонимно, по общей базе. Для класса G нужен чат,
поэтому эти запросы выполняются только с токеном пользователя в переменной
`GMART_TOKEN`; без токена они пропускаются.

## Качество

Задержку скрипт считает сам, а качество нужно разметить вручную. Для каждого
ответа добавьте в `labels.jsonl` строку
`{"label", "id", "run", "correct", "grounded", "citation_ok", "critical_error"}`.
Критические ошибки по плану: неверное число или единица измерения, потерянное
«не менее / не более», требование, перенесённое на другой вид объекта,
потерянное исключение, не та редакция, источник, который не подтверждает
утверждение. Изменение не принимается, если появилась хотя бы одна новая
критическая ошибка или выросла p95 задержки больше чем на 10 %.

## Переключатели оптимизаций

Каждый этап можно включить или выключить переменной окружения агента (по
умолчанию все включены). Так проводится A/B и откат без нового релиза:

| Этап | Переменная | Выключение |
|---|---|---|
| 1. Адаптивный критик | `DVD_ADAPTIVE_CRITIC` | `false` — всегда `DVD_CRITIC_REASONING_EFFORT` |
| 2. Детерминированный обход планировщика | `DVD_PLANNER_FAST_PATH` | `false` |
| 3. Создание чата вне критического пути | `DVD_DEFERRED_CHAT_SETUP` | `false` |
| 4. Контекст критика из процитированных источников | `DVD_CRITIC_CONTEXT` | `full` |
| 5. Узкий первый поиск с расширением | `DVD_SMALL_FIRST_RETRIEVAL` | `false` |
| 6. Постоянная MCP-сессия на запрос | `DVD_PERSISTENT_MCP_SESSION` | `false` |
